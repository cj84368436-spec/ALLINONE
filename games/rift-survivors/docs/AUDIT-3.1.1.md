점검 범위: 전투·18종 공격·상태 효과·성장·조작·결과 정산·저장·음원·화면·토스 빌드·공개 미리보기. 최신 런타임: 39715ec6d3b2a3048abfa98690eecc6fe8ede7a8. 기존 데이터 키와 이미 획득한 보석을 유지합니다.

## 검증 방법

- 정상 입력만 사용하는 기존 9개 고정 시드 완주 경로를 유지합니다.
- 지연된 토스 Storage 쓰기는 제어 가능한 비동기 가짜 브리지로 재현합니다. 실제 단말의 네트워크·네이티브 저장소 테스트를 대신하지 않습니다.
- 전투 회귀 검사는 실제 Game 로직으로 사망, 보스 처치, 기절, 만료와 넓은 충돌을 재현합니다.
- Chromium/WebKit에서 궁극기 표시·동시 방향키 회피·생성된 미리보기의 시작/저장/종료를 확인합니다.
- 공개 게임 검사는 저장소와 게시 HTML의 완전 일치를 기다린 뒤 실제 URL을 검사합니다.
- 최종 검사·빌드 상태와 파일은 [VALIDATION.md](VALIDATION.md)에 기록합니다.

## 다음 개선 우선순위

### 1. 화면 크기에 따른 난이도 편차

현재 main.js의 적 생성 거리는 화면 높이 ×0.46, 최소 330·최대 430입니다. 기존 완주 스크립트의 Game 기본값은 500입니다. 844px 높이 조건과 640px 높이 조건을 같은 게임 코드·시드·입력 정책으로 별도 실행했습니다.

- 844px 높이: 9회 중 7승, 기사 2/3·궁수 3/3·마법사 2/3.
- 640px 높이: 9회 중 6승, 기사 2/3·궁수 1/3·마법사 3/3.
- 작은 화면 궁수 seed 11은 약 45초, 큰 화면 동일 시드는 약 314초 승리. 제한된 자동 플레이 표본이며 사람의 승률을 추정한 수치가 아닙니다.

생성 거리와 화면의 정보량이 함께 바뀌므로 난이도가 기기마다 달라질 수 있습니다. 다음 밸런스 작업에서 기본 생성 거리와 위험 예고 기준을 통일하고 여러 화면 높이를 자동 완주 조건에 포함하는 것이 우선입니다. 이번에는 해당 설계값을 임의로 바꾸지 않았습니다. 근거: 저장소 .evidence/rift-3.1.1/audit/viewport-playthrough.json.

### 2. 후반 빌드가 다른 전투를 만들도록 진화 분기

직업마다 공격 6종이고 Lv.10에 6칸이 열려, 후반에는 보유 공격 구성이 비슷해집니다. 공격의 다발/집중/지속 분기와 독+화살 비, 빙결+번개 같은 조합 효과가 필요합니다. 피해 수치와 함께 공격의 동작·범위·대상 선택이 달라져야 합니다.

### 3. 전장과 적 편성의 변화, 다음 목표

현재는 한 전장·고정 시간 보스가 반복됩니다. 중간 보스 두 종류, 방패·자폭처럼 대처법이 다른 적, 두 번째 전장과 직업 업적을 우선합니다. 결과 화면에는 사용 기술과 피해 기여·다음 해금 목표를 보여주면 성장 이유가 명확해집니다.

### 4. 실제 iPhone 토스에서의 10분 이상 점검

조작 지연, 프레임 유지, 발열, 스피커·이어폰 음량, 백그라운드 복귀와 저장/종료를 실제 기기에서 확인해야 합니다. 현재 효과음 디코딩과 렌더링 자동 검사는 사람의 청감·재미·iPhone 성능을 증명하지 않습니다. 콘솔 연결과 실제 토스 기기 검증은 남아 있습니다.

### 개발 유지보수

전투와 렌더러가 큰 단일 파일이어서 다음 스킬 분기 추가 전에 공격 정의·상태 효과·결과 처리의 경계를 정리하는 것이 좋습니다. 3.1.1에는 미리보기 생성과 일치 검사를 추가했습니다. 의존성 잠금 파일을 저장소에서 관리해 빌드를 재현하는 작업도 다음 정리 대상입니다.
